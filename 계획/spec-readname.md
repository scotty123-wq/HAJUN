# 이름 읽고 고르기 — 그림을 보고 한글 이름 고르기 (읽기 학습 강화)

## 아빠 요구
> "문제도 그 글자를 듣고 그림을 고르는 형태가 있더라고. 이건보단
>  포켓몬 그림을 보고 1. 피카츄 2. 라이츄 3. 파이리 이런식으로 하는게 한글엔 더 도움될듯?"

**정확한 지적입니다.** 현재 `H_PIC` 은 방향이 반대라 읽기 연습이 전혀 안 됩니다.

```
현재 H_PIC   : 이름을 소리로 들려줌 → 그림 3개 중 고르기
             → 듣기 + 그림 인지만 시험. 한글을 읽을 일이 없음

새 유형      : 그림을 보여줌 → 한글 이름 3개 중 고르기
             → 한글 낱말 3개를 실제로 읽어야 함  ★ 읽기 학습의 핵심
```

## 만들 것 — `H_NAME` (가칭)

| 항목 | 내용 |
|---|---|
| 소재 | **포켓몬**(그림 있음) + **낱말**(이모지 있음) 양쪽 다 가능 |
| 화면 | 큰 그림/이모지 하나 + 보기 3개(**글자**) |
| 정답 | 그 그림의 이름 |
| 오답 | 아래 규칙 참고 |
| 난이도 | 2~3 정도. 오답을 얼마나 비슷하게 주느냐로 조절 |
| 보기 수 | 3 (초반) / 4 (실력이 붙으면) |

### 오답 만들기 — 여기가 학습 효과를 좌우합니다
너무 다르면 그림만 보고 찍고, 너무 비슷하면 좌절합니다.
- **쉬움**: 글자 수가 다르거나 첫 글자가 확연히 다른 이름 (피카츄 / 잠만보 / 뮤)
- **보통**: 글자 수가 같은 이름 (피카츄 / 라이츄 / 파이리)
- **어려움**: **첫 글자나 끝 글자가 같은 이름** (피카츄 / 라이츄 — 끝 글자 같음)
  또는 낱말이면 받침만 다른 것 (사과 / 사가 / 사관 은 부자연스러우니, 실제 낱말 중에서 고를 것)
- 난이도(`want`)에 따라 위 셋 중에서 고르세요
- **같은 진화 라인은 오답으로 쓰지 마세요** (피카츄 문제에 라이츄가 오답이면 헷갈릴 만하지만,
  진화 전후는 아이가 "둘 다 맞는 거 아니야?" 하고 혼란스러워할 수 있음 — 판단해서 결정하고 이유를 보고)

### 음성
문제를 낼 때 **이름을 소리로 알려주지 마세요.** 알려주면 읽을 필요가 없어집니다.
- 대신 "이 포켓몬 이름은 무엇일까?" 정도만
- **틀렸을 때**는 도움을 줘도 됩니다 (기존 완충 규칙: 2번 틀리면 정답이 반짝)
- 정답을 맞힌 뒤에는 이름을 읽어줘서 확인시켜 주세요

## 기존 `H_PIC` 은 어떻게 할까
**없애지 말고 남기되 비중을 줄이세요.**
- 가장 쉬운 유형이라 `SAFE_IDS`(두 문제 연속 헤맸을 때 나오는 안심 유형)로는 여전히 유용합니다
- 일반 출제에서는 `H_NAME` 이 주가 되게 하세요

## 절대 지킬 것
- `00-READ-FIRST.md` 공통 규칙 전부
- 기존 26종 구조(`QUIZ_TYPES` `pickQuizType` `pickSubject` `answerPick` `quizHead`) **재사용**.
  새 뼈대를 만들지 말고 기존 유형 하나를 복사해 변형하세요
- 보기가 **글자**이므로 `render:'text'`. 긴 이름(`메가이상해꽃` `거다이 피카츄`)이 있으니
  **`360×640` 에서 넘치지 않게** 글자 크기를 조절하세요
- 1~12차 코드 훼손 금지

## 검증
- 포켓몬 소재·낱말 소재 양쪽에서 정상 출제
- 오답이 정답과 겹치지 않는지, 보기 중복 0
- 난이도별로 오답 유사도가 실제로 달라지는지
- **긴 이름에서 화면 넘침 0** (`360×640` / `375×812`)
- 문제를 낼 때 이름을 미리 읽어주지 않는지
