# 낱말 소재 교체 — 학습 개편의 1단계 (가장 값싸고 효과 큰 조각)

전체 학습 대개편(`spec-quiz2.md`, 커리큘럼·적응형·획순·필살기)에서 **이 부분만 떼어낸 작업**입니다.
나머지는 나중에 따로 붙입니다. 여기서 커리큘럼 단계·적응형 로직·획순은 **하지 마세요.**

## 목표 (아빠 요구의 핵심)
> "문제가 너무 지금 포켓몬에 집중되있는것같아서 한글에 확장성에 한계가 잇는것같아"
> "하준이가 모르는 낱말도 공부를 하려면 해야하니 낱말은 무조건 많은게 좋지
>  말을 다하니깐 사실 단어는 거의 다 안다고 생각해도되 다만 그 읽거나 쓰기를 못하는거니깐"

현재 퀴즈 15종이 **전부 야생 포켓몬 이름**을 소재로 씁니다. 61마리를 다 외우면 한글 학습이 멈춥니다.
`계획\words.md` 에 **낱말 990개**가 준비돼 있습니다. 이걸 문제 소재로 끌어오는 게 이번 작업 전부입니다.

## 핵심 설계 — 유형은 그대로, 소재만 갈아끼움
**새 문제 유형을 만들지 마세요.** 기존 15종의 `build(wm)` 이 받는 인자만 바꿉니다.

```js
// openQuiz() 안에서 이 한 줄이 핵심
const subj = pickSubject(t, wm);   // 포켓몬 또는 낱말
const q = t.build(subj);
```

`subj` 는 기존 `wm`(MONS 객체)과 **오리 타이핑 호환**이어야 합니다:
```js
// 포켓몬일 때 — 기존과 동일하게 동작해야 함
{ n:'피카츄', mon:MONS[12], mi:12, isMon:true }
// 낱말일 때
{ n:'사과', emoji:'🍎', cat:'음식', isMon:false }
```

## 할 일
1. `계획\words.md` 의 `const WORDS` 블록을 **`game.html` 안에 인라인**으로 넣기 (990개)
   - 용량이 커지니 형식을 간결하게. 카테고리별 배열 구조 유지
2. `WORD_ALL` 평탄화 배열 생성
3. `pickSubject(t, wm)` — 포켓몬이냐 낱말이냐 결정
   - 기본 비율 **포켓몬 4 : 낱말 6**
   - `H_PIC`(그림 고르기), `N_LV`(레벨 덧셈)는 **무조건 포켓몬**
   - **처음 만난 포켓몬**이면 포켓몬 확률 상향(0.6) — 잡으면서 이름 배우는 재미
   - **전설**이면 더 상향(0.75)
   - 직전 문제가 포켓몬이었으면 하향 — 연속 방지
   - 최근 12개 낱말은 다시 안 나오게 (`S.wRecent`)
4. 15종 `build()` 전부 `wm.n` → `s.n` 으로 교체. `H_PIC` 만 `s.mi` 사용
   - 각 유형의 `ok()` 조건도 낱말에 맞게 (글자수 조건 등)
   - **`H_ORDER` 는 `s.n.length` 가 2~4 인 것만** (5글자면 화면 칸이 너무 작아짐)
5. `quizHead()` — 지금 무조건 야생 포켓몬 그림을 그립니다. `q.subj` 를 보게 변경
   - 낱말이면 **이모지를 크게** 표시 (`.qemoji { font-size:clamp(48px,17vw,84px) }`)
   - **낱말 문제일 때도 야생 포켓몬은 화면 어딘가에 계속 보여야** 합니다 (잡으려는 동기 유지).
     작게 코너에 두는 배치 권장
6. `hearQuiz()` / `speak()` — 낱말도 자연스럽게 읽어주기
